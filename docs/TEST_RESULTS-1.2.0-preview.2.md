## Corrected security-session boundary

Build 14 was an **unreleased internal candidate**. Its v1 XPC helper did not set `JoinExistingSession`, so the helper and viewer used different macOS security sessions. The earlier **13-check `VAULT_HARNESS` lab** used an explicitly unlocked private synthetic Keychain; that lab did not establish access through the normal default login-Keychain path. A real build 14 Remember attempt could therefore remain unconfirmed despite successful VNC authentication.

Build 15 uses the **separately versioned public v2 helper** with `JoinExistingSession=true`, a separate connection service and password namespace. The actual-public-helper 17-check run above used the default login Keychain without unlocking it or adding test hooks. See the [current v2 manifest](../native/credential-vault/frozen-manifest.json) and [preserved historical v1 manifest](../native/credential-vault/v1/frozen-manifest.json). The old v1 helper, source and protected items are preserved; preserving v2's signed bytes and publisher identity remains necessary for new-entry continuity across viewer updates.

Legacy reads are explicit and read-only. They succeed only when macOS already authorizes access; the protected synthetic v1 item was safely denied and unchanged. This does not prove recovery of any owner's older password. No ACL reset, Keychain unlock/reset, trust/search-list change, authentication UI or plaintext fallback is introduced. An unconfirmed save disables automatic use even if a protected copy may remain; Forget records suppression before its RPC, including when acknowledgment is lost.

Published previews use a **project self-signed publisher certificate**, with Apple Developer ID signing and notarization pending. Public-CI/source builds without private publisher material are **ad hoc development builds with persistent credential service unavailable**; manual VNC connections remain available. Their successful build does not establish publisher-vault continuity or stable-release certification.

## Behavior retained and limits

- New browser cards default to **Lantern · inside this window**. Explicit choices **Safari · opens outside Lantern** and **Google Chrome · opens outside Lantern** open the real installed browser with its own profiles/extensions. Cards do not embed it, read profiles, capture windows or use Apple events, CDP or synthetic input. Exact external window/tab/profile focus is not guaranteed.
- Internal WebKit retains its separate session, up to 12 tabs per window and six loaded internal windows. Background previews remain about ten seconds; selected-thumbnail sampling pauses after an initial image while main views run normally. Live/connecting order stays stable on selection; offline/sleeping/closing cards move down.
- The existing renderer and viewport still match the [build 13 preservation receipt](release-evidence/1.2.0-preview.1/renderer-preservation.json). This is an unchanged-source check, not a fresh GPU or physical-monitor test. VNC picture presets, decoded quality, remote resolution and passive RTT are unchanged.
- Owned Baidu diagnostics reproduced completed search redirects to its verification page with HTTP 200 and `isLoading == false`, while homepage loads were normal. They did not fully reproduce every persistent-busy report or determine the site's verification reason. No verification bypass, production user-agent spoofing or ATS/TLS weakening is claimed.
- VNC encryption, a built-in VPN/SSH tunnel, Intel support, VNC file transfer, remote audio/printing/recording, full public-site/OAuth compatibility and physical display-transition coverage are not provided or established. This remains a preview.

The [Preview 1 report](TEST_RESULTS-1.2.0-preview.1.md) and earlier versioned reports remain historical. Their results are not silently promoted to new build 15 runtime results.
