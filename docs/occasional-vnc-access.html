VNC for occasional Mac access

A quick check on another computer should start with a reachable server and clear connection details. If a RealVNC workflow does not fit this occasional task and you prefer a direct viewer without another account, Lantern can open that existing VNC desktop from your Mac.

Privacy & choices

VNC is a way to view and control a desktop that a server shares. Lantern is the viewer; it does not install the server or turn a Remote Desktop/RDP endpoint into VNC. Use a computer you own or have permission to access.

If you are comparing viewers with RealVNC

RealVNC’s macOS download FAQ, checked on 21 November 2026, distinguishes connections to licensed RealVNC servers from third-party VNC servers. It says the latter require a paid plan; connecting to a licensed RealVNC server can use its viewer without a separate viewer subscription after account sign-in. Check its current terms for your setup.

Lantern’s free preview is another option when you already have a compatible VNC server, such as TightVNC, and want a direct viewer without a Lantern account. It does not replace RealVNC cloud sessions, a managed support service, or a server’s required authentication and encryption methods.

  1. Check the existing server

    Confirm that the VNC server is running on the other computer. Choose Find… next to Server to search your current private Wi-Fi or Ethernet network on the selected TCP port. A single result is selected automatically. Confirm an alias such as Office PC and choose Save Computer to add it to your list. If it is not found, enter its reachable address manually. You still need its VNC password if authentication is enabled. The usual port is 5900, but your server may use another value. Enter a TCP port, not a VNC display number.

    Use the password configured for VNC. It may differ from the computer’s Windows or macOS account password. Classic VNC authentication uses only the first eight password bytes.

  2. Use a trusted connection

    Connect over a trusted local network, or establish your own VPN or SSH tunnel first. Lantern’s current build does not encrypt VNC traffic and does not create a tunnel for you. An unencrypted VNC port exposed directly to the public internet is unsafe.

    If you use a separately configured tunnel, connect to the host and forwarded TCP port that tunnel provides. Guest Wi-Fi isolation or a firewall can still prevent access even when both machines have internet service.

  3. Open Lantern and find your place

    Enter the server and port, add the VNC password, and choose Connect. New connections start in Fit to Window; each server reopens with its last viewing mode and picture-quality choice. Window size and position are also restored across launches, adjusted when needed to remain reachable. For readable detail on a large desktop, choose Auto (Readable) to avoid shrinking below 100%. Use the visible scroll bars or turn on Hand to pan locally by dragging, scrolling, or using arrow keys.

    Press Escape or turn Hand off before controlling the remote computer. With Hand off, normal scrolling goes to the remote app. Choose Fit to Window for an overview; local zoom never changes the server’s resolution.

    The RTT line below connection status shows a passive TCP round-trip estimate once a second while connected. It is not input-to-screen delay, and a tunnel may make it describe the forwarding endpoint. Read the RTT status explanation if the desktop lags despite a low value.

  4. Disconnect when you finish

    Choose Disconnect to end your viewing session. Closing the viewer does not disable the VNC server or change its firewall settings. If you temporarily enabled server access for this task, turn it off again or restore its previous access settings as appropriate.

    For repeat visits, save a device profile. Lantern supports three saved devices and one selected for control; connected background sessions can keep showing sampled previews. Profiles contain a name, host, and port; passwords are not saved in profiles. Remember password is off by default; when you opt in, macOS login Keychain saves the endpoint’s password after a successful connection. Choose Remember before connecting; disconnect before changing it or unchecking it to request deletion of the saved password.

    All Keychain reads, saves, and removals forbid authorization dialogs. Errors appear inline; a failed save turns Remember password off, and inaccessible older items are left unchanged. You can always enter the server’s VNC password manually. Newly saved passwords use a fixed, signed v2 helper in the viewer’s existing macOS security session. Seventeen checks exercised the actual public helper with synthetic entries in the default login Keychain, without unlocking it or enabling authentication UI. Older items are read only when macOS already permits access; a protected synthetic v1 item was denied and left unchanged. This does not establish recovery of an owner’s older password.

Need your regular browser too?

New browser cards default to Lantern’s internal WebKit browser. Explicitly choosing installed Safari/Chrome opens the actual browser outside Lantern. Installed-browser cards open outside Lantern with the profiles and extensions those apps already manage; they do not auto-launch on restoration or close the browser when removed. Use Open Website to open a saved address again. Internal WebKit has Stop while loading and Reload afterward. Read the browser choices.

A small setup, with clear limits

The existing renderer reduces local copying for partial screen updates and can service queued input while an update arrives. It preserves decoded pixels, picture presets, and server resolution; it does not change VNC network compression or promise faster Wi-Fi.

Lantern is free for ongoing use, with no Lantern account, subscription, expiry, or payment requirement. The current 1.2.0 Preview 2, build 15, uses a project self-signed publisher certificate; Apple Developer ID signing and notarization remain pending. It requires macOS 13 or later on Apple Silicon. Review the Mac VNC client guide for compatibility, transport, and feature limits before relying on a particular setup.

Need help with a failed connection or a desktop edge you cannot reach? The Wiki covers setup and troubleshooting. You can send feedback or inspect the source code.
