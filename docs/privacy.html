A CLEARER VIEW OF YOUR DATA

Lantern stays free, with no login required. This page explains the website’s first-party usage counts and what happens when you choose to send a poll response or feedback.

Your browser, your choice

Automatic website counts

Checking your browser preference…

No counts are sent when Global Privacy Control or Do Not Track is enabled.

Your preference is kept locally when browser storage allows it. Stopping counts affects future automatic events; it does not remove past aggregate counts. You can still explicitly send poll answers or feedback.

What automatic counts include

When enabled, the website sends a visit event when a page opens, an interest-panel event when that panel opens, and a download event when a Mac app download link is clicked. These requests go to Lantern’s first-party service at lantern-vnc-mac.fts227.chatgpt.site.

  • A random browser UUID stored locally, and a separate event UUID to avoid counting retries twice.
  • The event type and a fixed public page path. The path excludes query strings, fragments, and arbitrary private path values.
  • The referring site’s host, with its path and query removed before transmission.
  • General campaign labels from utm_source, utm_medium, and utm_campaign, if present. These labels are length-limited; use campaign names rather than personal information.
  • The date and approximate country, when the host provides it; otherwise the country is unknown. Stored usage data includes country only, not raw IP addresses or precise location.

The website uses no analytics cookies or browser fingerprinting. Automatic counts are enabled by default unless you opt out here or your browser sends Global Privacy Control or Do Not Track. The Mac app does not inherit this website counting code.

A browser ID is not a person

The random ID helps estimate distinct browsers. It is not an account, real name, or verified person. Clearing storage, using another browser, blocking storage, or changing devices can create another ID. If persistent storage is blocked, the website falls back to session storage or a temporary in-memory ID.

Stopping automatic counts removes the saved Lantern usage ID and suppresses future automatic events. If storage is blocked entirely, an on-page preference may not survive navigation; Global Privacy Control or Do Not Track provides a browser-level signal across visits.

Answers and messages you choose to send

The interest poll sends your usefulness choice and future-support intent only when you choose Save my response. It is not a payment, pledge, subscription, or checkout. No card or payment information is requested.

The feedback form sends the selected category—thanks, idea, or bug—and your message only when you choose Send feedback. Messages must be 3–4,000 characters. A confirmed save returns a ticket ID. Until that confirmation arrives, the form keeps your entries and lets you retry with the same request UUID.

Both forms include a random browser UUID and an event UUID for a shared save without a login. If automatic counts are off, a temporary ID lets an explicit submission work without retaining a new automatic-count identifier. These optional submissions still work when usage counting is off.

Do not include passwords, private server details, clipboard contents, or other sensitive information. Feedback messages are available for private review by the project owner; they are not published as a public feed. A direct GitHub issue is a separate option and is public under GitHub’s own service rules.

What the project owner can see

The owner-only dashboard shows aggregate totals and breakdowns: visits, browser IDs, interest-panel opens, app download-link clicks, poll responses, feedback categories, referrer sources, countries, campaign labels, and daily visits. Access requires the owner’s sign-in. These metrics are not published on the public website.

These are first-party browser counts, not audited people or confirmed installations. Automated visits may be included. A download count records a link click, not proof that a download finished or that Lantern was installed. Poll responses express submitted opinions, not a representative survey or a purchase commitment.

The poll keeps one response per browser ID; another save updates that browser’s choices. Usage event records use a 90-day window, with expired events cleaned up as new activity is processed. Feedback remains available for owner review. No public endpoint exposes feedback messages or individual browser identifiers.

The Mac app and network connections

Lantern’s Mac viewer connects directly to your VNC servers. Saved computers with an accessible remembered password can reconnect for previews when the app opens. Background sessions become read-only with updates paced about every ten seconds; only the selected computer receives remote input and optional clipboard sharing. Website counts do not add a cloud relay, account requirement, or telemetry system to the app. The app’s Save Feedback… command still saves a local text file for you to review and share.

Remembered VNC passwords use macOS login Keychain only when you opt in and a connection succeeds; plaintext passwords are not stored in device profiles or app preferences. All Keychain reads, saves, and removals forbid authorization dialogs. Errors appear inline; a failed save turns Remember password off, and inaccessible older items are left unchanged. Manual VNC-password entry remains available, without a plaintext-storage fallback. Current ad hoc builds can lose access to saved Keychain passwords across app updates; a secure fix for that limitation has not yet been verified.

Computer and browser thumbnails are sampled into RAM only, never saved as screenshots. Background preview work is paced about every ten seconds; repeated sampling pauses for the selected screen after an initial thumbnail while the main view runs normally. Saved computer/browser-window names, tab titles/URLs and selected-tab identifiers remain in local preferences. Browser screens use Lantern’s own persistent WebKit cookies and website storage, separate from Safari and Chrome; their data is not imported. Websites you open receive normal network requests and may collect information under their own privacy policies. Loaded background tabs can keep running scripts and network requests until their window sleeps, they close, or they are removed. Each browser-window card can keep up to 12 tabs; at most six windows stay loaded. Tabs load lazily, and sleeping windows restore recorded tab URLs and selection on demand, potentially losing unsaved forms or page state.

Website browsing does not add a Lantern app-analytics service. If you visit this project website inside a browser screen, its website counts and choices described above apply just as they do in other browsers. HTTP authentication and credential authorization dialogs are disabled; no browser feature changes the noninteractive Keychain policy.

For app connection and clipboard details, read the Wiki FAQ. Website hosts and network infrastructure necessarily process requests to deliver these pages; this page describes the data handled by Lantern’s counting and feedback features.

A question or a rough edge?

You can send feedback without a login or open a public GitHub issue. Leave sensitive information out of either route.
