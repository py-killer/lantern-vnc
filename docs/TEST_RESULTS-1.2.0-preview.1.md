# Tabbed workspace preview validation — 22 November 2026

Candidate: **1.2.0-preview.1, build 13**, native arm64 for macOS 13 or later. Build 13 changes only sidebar card ordering. Its fresh 142-check workspace/order run passed; the unchanged browser, UI, settings, store, sampler, card and protocol implementation retains the passing component evidence below. Retained counts are not presented as new build 13 test runs.

Tests use owned offscreen AppKit windows, synthetic pixels, isolated preferences, fake credential storage and loopback VNC/HTTP fixtures. They do not use personal desktops, real user credentials, global input automation or external websites.

## Behavior and limits

- Keep up to three saved VNC computer profiles. Background sessions are read-only with update requests/previews paced about every ten seconds. Only the selected computer feeds the shared renderer and receives remote input/optional clipboard sharing. After an initial thumbnail, repeated selected-screen sampling pauses while its main desktop/page runs normally. Previews are RAM-only samples, not saved screenshots or latency measurements.
- Keep live and connecting cards in saved order; selecting a card does not move it. Offline, sleeping or closing screens move to the bottom and return to their original live-card position when available again.
- Each browser card is a local WebKit window with up to 12 tabs. New tabs, selection, closing and popup tabs stay inside that card. Save tab URLs/titles and selection; migrate previous single-address cards into one-tab windows with their alias and URL intact. An unnamed new window gets a numbered Browser alias, and closing its last page leaves a fresh new tab.
- Keep up to 100 saved browser windows and at most six loaded windows. Tabs load lazily. Least recently used inactive windows sleep and restore saved tabs on demand, which can discard unsaved forms/page state. Loaded background tabs can keep running scripts/network requests. Lantern uses its own persistent website session separate from Safari/Chrome; test controllers use an ephemeral store.
- Downloads are unsupported and reported inline. HTTP authentication/credential authorization dialogs are disabled. Some popup/OAuth and other full-browser behavior may remain incompatible; a full browser is still needed for those cases.
- The recorded MetalDesktop/DesktopViewport source hashes remain unchanged. Decoded pixels, VNC picture presets, server resolution, passive RTT and local window restoration are preserved. Preview pacing is not adaptive compression or a network/end-to-end speed guarantee.
- All Keychain methods remain noninteractive. Ad hoc updates can still lose access to earlier saved items. **Cross-update password continuity remains unresolved** in [issue #2](https://github.com/py-killer/lantern-vnc/issues/2); there is no ACL weakening, plaintext fallback or migration-fix claim.
- VNC transport encryption, a built-in VPN/SSH tunnel, Intel support, VNC file transfer, remote audio, recording and printing are not provided. Developer ID signing, notarization, physical display transitions and the complete manual hardware matrix remain pending. This is a preview, not a stable-release certification.
